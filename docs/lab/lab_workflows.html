Lab 10: End-to-End ML Workflows

Overview

This lab puts the full ML workflow in your hands. Rather than walking through a guided example, you will apply each step to a dataset of your choice. The one concept we will walk through in detail before you begin is pipelines — the scikit-learn tool that keeps your workflow clean and prevents data leakage.

The steps you will follow:

  1. Understand the big picture
  2. Get the data and do a preliminary exploration
  3. Create a representative test set and lock it away
  4. Explore the training data to gain insights
  5. Consider feature combinations
  6. Prepare training data using a Pipeline
  7. Try candidate models and estimate performance with CV
  8. Select a model and fine-tune it
  9. Evaluate on the test set

Pipelines

Why use a Pipeline?

When you preprocess data, there is a tempting shortcut: fit the scaler (or imputer, or encoder) on the entire dataset before splitting. Don’t do this. Doing so leaks test-set statistics into training and produces an overly optimistic performance estimate — called data leakage.

A scikit-learn Pipeline chains transformers and a final estimator into a single object. When you call .fit() on a pipeline, each transformer is fit on training data and then used to transform it before passing the result to the next step. When you call .predict() or .transform() on new data, the pipeline applies the already-fit transformers in sequence. The test set is never seen during fitting.

Building a Pipeline

The simplest pipeline chains steps in a list of (name, object) tuples:

Code 
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LinearRegression

numeric_pipeline = Pipeline([
    ('imputer', SimpleImputer(strategy='median')),  # fill missing values
    ('scaler',  StandardScaler())                   # standardize
])

Each step name (the first element of each tuple) is arbitrary but must be unique. You can access any step later via pipeline.named_steps['step_name'].

Handling mixed feature types with ColumnTransformer

Real datasets usually have a mix of numerical and categorical columns that need different preprocessing. ColumnTransformer applies different pipelines to different column subsets and concatenates the results:

Code 
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import OneHotEncoder

num_features = ['temp', 'humidity', 'wind_speed']
cat_features = ['land_use']

categorical_pipeline = Pipeline([
    ('encoder', OneHotEncoder(drop='first', sparse_output=False))
])

preprocessor = ColumnTransformer([
    ('num', numeric_pipeline, num_features),
    ('cat', categorical_pipeline, cat_features)
])

Combining the preprocessor with a model

The cleanest approach is to wrap the preprocessor and the final model together in one top-level pipeline. This means you can pass raw X_train and X_test directly — the pipeline handles all transformations internally:

Code 
from sklearn.ensemble import RandomForestClassifier

full_pipeline = Pipeline([
    ('preprocessor', preprocessor),
    ('model',        RandomForestClassifier(random_state=42))
])

# Fit on raw training data — transformers only see X_train
full_pipeline.fit(X_train, y_train)

# Predict on raw test data — transformers apply saved statistics
y_pred = full_pipeline.predict(X_test)

This also makes cross-validation and grid search straightforward, because GridSearchCV will refit the whole pipeline (including the preprocessor) on each fold:

Code 
from sklearn.model_selection import GridSearchCV

param_grid = {
    'model__n_estimators': [50, 100, 200],
    'model__max_depth':    [None, 5, 10],
}

grid_search = GridSearchCV(full_pipeline, param_grid, cv=5,
                           scoring='neg_mean_squared_error')
grid_search.fit(X_train, y_train)

Note the double-underscore syntax: 'model__n_estimators' means the n_estimators parameter of the step named 'model' in the pipeline.

The Datasets

Choose one of the datasets below. Each is publicly available, contains a mix of feature types, and has a clear environmental prediction target. Load the data, read the documentation for each column, and then follow the workflow template in the next section.

Option 1: Global Air Pollution — Kaggle

City-level air quality data from ~23,000 locations worldwide, sourced from government monitoring agencies and aggregated by AQI category. Features include country, city, CO AQI value, Ozone AQI value, NO2 AQI value, and PM2.5 AQI value.

  • Task: Regression — predict overall AQI value, or classification — predict AQI category (Good / Moderate / Unhealthy / etc.)
  • Interesting challenge: Strong multicollinearity among pollutant columns; some cities have very sparse records
  • Access: Download from Kaggle
df = pd.read_csv('global_air_pollution_dataset.csv')

Option 2: Coral Reef Bleaching — Kaggle

Reef-level observations compiled from global monitoring surveys spanning 1980–2020. Each row is one survey visit; features include year, ocean region, depth, sea surface temperature anomaly, Oceanic Niño Index, and local stressor scores.

  • Task: Regression — predict bleaching severity percentage, or classification — predict bleaching presence/absence
  • Interesting challenge: Surveys are spatially and temporally clustered; the target is zero-inflated with occasional extreme values
  • Access: Download from Kaggle
df = pd.read_csv('CoralBleaching.csv')

Option 3: Palmer Penguins

Morphological measurements of 344 penguins from three species (Adelie, Chinstrap, Gentoo) collected at Palmer Station, Antarctica. Features include bill length and depth, flipper length, body mass, sex, and island.

  • Task: Classification — predict penguin species, or regression to predict body mass
  • Interesting challenge: Small dataset; missing values in sex and some measurements
  • Access: Install the Python package
# pip install palmerpenguins
from palmerpenguins import load_penguins
df = load_penguins()

Option 4: Water Potability

Chemical measurements of 3,276 water samples. Features include pH, hardness, dissolved solids, chloramines, sulfate, conductivity, organic carbon, trihalomethanes, and turbidity.

  • Task: Classification — predict whether a water sample is safe to drink (binary)
  • Interesting challenge: Class imbalance; significant missing values in several columns
  • Access: Download the CSV from Kaggle or the mirror on the course data page
df = pd.read_csv('water_potability.csv')

Option 5: Drought Prediction — US Meteorological Data

Weekly meteorological summaries (temperature, precipitation, soil moisture, wind, humidity, and more) for US counties paired with the U.S. Drought Monitor category (None, D0–D4). Contains ~100,000 rows spanning 2000–2020.

  • Task: Classification — predict drought severity category
  • Interesting challenge: Temporal autocorrelation; class imbalance across drought levels
  • Access: Download from Kaggle
df = pd.read_csv('train_timeseries.csv')

Step 7: Fit Candidate Models with Cross-Validation

Combine your preprocessor and at least three candidate models into full pipelines. Evaluate with 5-fold CV.

Code 
from sklearn.model_selection import cross_val_score
from sklearn.linear_model import LinearRegression       # swap for LogisticRegression if classifying
from sklearn.neighbors import KNeighborsRegressor       # or KNeighborsClassifier
from sklearn.ensemble import RandomForestRegressor      # or RandomForestClassifier

scoring_metric = 'neg_mean_squared_error'  # change to 'accuracy' or 'f1' for classification

candidates = {
    'Linear'        : LinearRegression(),
    'KNN (k=5)'     : KNeighborsRegressor(n_neighbors=5),
    'Random Forest' : RandomForestRegressor(n_estimators=100, random_state=42),
}

results = {}
for name, model in candidates.items():
    pipe = Pipeline([('preprocessor', preprocessor), ('model', model)])
    scores = cross_val_score(pipe, X_train, y_train, cv=5, scoring=scoring_metric)
    results[name] = {'Mean CV score': scores.mean(), 'Std': scores.std()}

pd.DataFrame(results).T.round(4)
NoteQuestion 6
  1. Which model performs best based on mean CV score?
  2. Does any model beat your baseline from Step 1?

Step 8: Fine-Tune the Best Model

Use GridSearchCV on the full pipeline (preprocessor + model). Note the model__ prefix for accessing hyperparameters inside the pipeline.

Code 
from sklearn.model_selection import GridSearchCV

best_model_name = 'Random Forest'  # replace with your choice
best_model      = RandomForestRegressor(random_state=42)

full_pipeline = Pipeline([
    ('preprocessor', preprocessor),
    ('model',        best_model)
])

param_grid = {
    'model__n_estimators': [50, 100, 200],
    'model__max_depth':    [None, 5, 10],
}

grid_search = GridSearchCV(full_pipeline, param_grid, cv=5,
                           scoring=scoring_metric, n_jobs=-1)
grid_search.fit(X_train, y_train)

print('Best params:', grid_search.best_params_)
print(f'Best CV score: {grid_search.best_score_:.4f}')

Step 9: Evaluate on the Test Set

Use the locked-away test set exactly once.

Code 
from sklearn.metrics import mean_squared_error  # or accuracy_score, etc.

y_pred   = grid_search.best_estimator_.predict(X_test)
test_mse = mean_squared_error(y_test, y_pred)

print(f'Test MSE  : {test_mse:.4f}')
print(f'Test RMSE : {np.sqrt(test_mse):.4f}')
